# Bewertung der Einrichtung

Stand: 22.10.2026. Frage: Versteht jemand, der das Programm nicht kennt, in jedem Schritt, was er tut und warum?

## Kurz gesagt

Nein, noch nicht ganz. Bedienung und Ablauf sind gut. Es fehlt aber oft das Warum. Die Einrichtung sagt meistens, was man tun soll. Sie sagt selten, wozu es gut ist und was passiert, wenn man es weglässt. Dazu kommt: Die Liste der Funktionen ist veraltet, und eine Auswahl der Features fehlt.

## Was schon gut ist

- „Schritt 2 von 8“ wird angesagt. Man weiß immer, wo man ist.
- Fast alles lässt sich überspringen. Die Zusammenfassung sagt, wo man es später nachholt.
- Eine Zeile pro Satz. Das lässt sich gut mit der Braillezeile lesen.
- Seiten, die man nicht braucht, fallen weg.

## Probleme Seite für Seite

### 1. Willkommen

- Die Liste „In diesem Programm erwartet Sie“ ist veraltet. Es fehlen Neuigkeiten, Aktivität, Issues, Paketübersicht, Konflikte lösen und anderes.
- Es fehlt ein Satz dazu, was ein Code-Projekt ist und für wen das Programm gedacht ist.
- Es fehlt ein Überblick über die Schritte, zum Beispiel: „Sie richten nacheinander ein: Zugangsdaten, Git, GitHub, Ordner, Features und KI. Das dauert etwa 5 bis 15 Minuten.“

### 2. Zugangsdaten schützen

- Diese Seite kommt als zweite, bevor man weiß, wofür man Zugangsdaten braucht. Sie ist mit 11 Zeilen sehr lang.
- Sie nennt Beispiele, die es im Programm nicht gibt, etwa „Automatisierung“ und „E-Mail-Konto“. Das verwirrt.
- Vorschlag: zuerst ein Satz zum Warum. Zum Beispiel: „Für GitHub und manche KI brauchen Sie einen geheimen Schlüssel. Das Cockpit bewahrt ihn sicher auf.“ Danach die zwei Wege und eine klare Empfehlung. Die Einzelheiten kommen nach hinten.

### 3. Git

- Ist Git schon installiert, steht nur „Git ist installiert“. Ein Neuling erfährt nicht, was Git ist.
- Fehlt Git, steht nur „Ohne Git kann das Cockpit keine Änderungen hochladen.“ Das ist zu wenig.
- Es fehlt ein Satz wie: „Git merkt sich jeden Stand Ihres Codes. So können Sie zu jedem früheren Stand zurück. Das Cockpit braucht Git für fast alles.“

### 4. Code-Plattformen wählen

- Das Wort „Git-System“ verwechselt man leicht mit Git aus Schritt 3.
- Es fehlt die Erklärung, was GitHub ist. Zum Beispiel: „GitHub bewahrt Ihren Code im Internet auf, als Sicherung, zum Teilen und zur Zusammenarbeit. Es ist kostenlos.“
- Es fehlt der Hinweis, dass man ein Konto braucht und GitHub auch weglassen kann.
- Der Text steht in einem einfachen Label, nicht in einer Liste wie auf den anderen Seiten.

### 5. Code-Plattformen einrichten

- Es wird nicht gesagt, was beim Einrichten passiert: anmelden oder Schlüssel eintragen, Name und E-Mail für Git.
- Warum Git Name und E-Mail braucht, wird nicht erklärt. Ein Satz würde reichen: „Er steht bei jeder Ihrer Änderungen.“

### 6. Projekte-Hauptordner

- Das ist weitgehend klar.
- Es fehlt ein Satz dazu, dass das Cockpit vorhandene Projekte in diesem Ordner findet und dort nichts verändert.

### 7. KI

- Es wird nicht konkret gesagt, was die KI macht. „Auf ein anderes Level bringen“ ist zu vage. Besser sind Beispiele: Commit-Nachrichten vorschlagen, Fehlermeldungen erklären, Fragen zur Bedienung beantworten, diktieren.
- „Sprach-KI“ wird nicht erklärt. Gemeint ist die Spracheingabe.
- Lokal oder extern: Der Unterschied fehlt. Lokal heißt, alles bleibt auf dem Rechner und ist kostenlos, braucht aber einen Download von mehreren GB und genug Arbeitsspeicher. Extern heißt schnell, aber die Daten gehen ins Internet und es kostet eventuell Geld.
- Größe und Dauer des Downloads stehen nicht vorher da.

### 8. Zusammenfassung

- Der erste Satz „Perfekt, Sie haben folgende Tools eingerichtet“ passt nicht, wenn danach „Übersprungen“ steht. Besser: „Die Einrichtung ist fertig. Hier sehen Sie, was eingerichtet ist und was nicht.“
- Es fehlt der erste Schritt danach, zum Beispiel: „Im Cockpit sehen Sie die Liste Ihrer Projekte. F1 zeigt die Hilfe, im Menü Hilfe finden Sie die Kurzanleitungen.“

## Neue Seite: Features wählen

Ihr Wunsch: Alle Features, die nichts zum Einrichten brauchen, stehen in einer Liste. Alle sind angehakt. Man kann sie abwählen, jetzt oder später pro Projekt.

Vorschlag:

- Die neue Seite kommt nach „Projekte-Hauptordner“ und vor „KI“.
- In der Liste stehen die Features ohne KI und ohne Konto. Zurzeit sind das Versionen, Exe-Erstellung, Paketübersicht, Neuigkeiten und Aktivität. Neue Features erscheinen von selbst.
- Jede Zeile beginnt mit dem Namen, danach ein kurzer Satz, was das Feature tut. Mit der Leertaste haken Sie an oder ab.
- Alle sind angehakt, auch „Versionen“, das bisher aus war.
- Was Sie abwählen, ist überall aus. Was angehakt bleibt, ist in allen Projekten an. Pro Projekt ändern Sie es später in der Feature-Verwaltung.
- Features mit KI kommen auf die Seite KI, Features mit GitHub auf die Seite Code-Plattformen. Dort jeweils als Liste mit dem Satz: „Diese Features können Sie nutzen, wenn …“. So sieht man, wozu man das einrichtet.
- Die Zusammenfassung nennt, wie viele Features an sind.
